## Deviations from Design

1. **Hand-rolled YAML parser** instead of `yaml` package. The `yaml` package is a transitive dep of Astro (via `@astrojs/check`), but pnpm's strict hoisting prevents `import 'yaml'` from user code without listing it as a direct dep. The constraint forbids new packages, so we ship a ~100 LoC parser that handles the Doorstop subset (maps, lists, quoted strings, multiline via the migration script's single-line output). If the project later adopts `yaml` as a direct dep, `loader.ts` can swap implementations in one place.

2. **In-house `node.d.ts` shim** instead of `@types/node`. Same constraint: the project has no `@types/node` devDep, so we declare the ~15 functions/types the loader actually uses. Adding `@types/node` would bloat the type surface beyond the change's needs.

3. **`scripts/requirements/req/*.yml` regenerated as part of C0.** The pre-existing YAMLs in the working tree were generated by `doorstop` CLI (with wrapper metadata `active`, `derived`, `reviewed`, etc.). The migration script produces a leaner shape. Per the design (DP1=A: migration script is the source of truth) and the user's rule ("only via `migrate_to_doorstop.py`"), the migration regenerates them. `doorstop` CLI can be re-run later to restore the wrapper metadata.

## Deviations from Design

1. **Translator passed as `t` prop** instead of importing `useTranslations()`. The 32 `rem.*` i18n keys land in BATCH 2b (Task 3.3, C5) where `i18n/types.ts` + `locales/{es,en}.ts` are extended. Touching `i18n/` is explicitly out-of-scope for 2a. `format.ts` was the precedent for the `(key: string) => string` shape; the new components mirror it.
2. **`Locale` type imported from `lib/rem/config.ts` removed** — `src/lib/rem/types.ts` does not export `Locale`. Imported `Locale` from `src/i18n/config.ts` instead. Both files export the same union via different roots.
3. **Skeleton hydration state uses `requestAnimationFrame` (with `setTimeout` fallback)**. The first-paint `aria-busy="true"` must remain visible for the synchronous test assertion. jsdom's rAF polyfill is version-fragile, so the impl schedules both; whichever fires first flips the state.
4. **`.astro` component tests target helpers, not direct render**. The project has no Astro container API at this Vitest version. `RemFieldRow.test.tsx` + `RemError.test.tsx` assert on the pure helpers (`getFieldRowVariant`, `getErrorVariant`) plus a static smoke-read of the `.astro` source for the `aria-label` / `data-rem-error-code` contracts.
5. **Prettier reformatted ~74 files in the working tree during B1** (see `git status`). Those changes are out of scope for 2a and remain uncommitted; the orchestrator's "DO NOT touch … format" rule scoped 2a to the new components.
6. **vitest.config.ts NOT extended with coverage thresholds yet** (`src/components/rem/**` was added in this batch — Task 2.5 of design says PR3's Task 4.2 owns the threshold extension; deferring to stay inside 2a's scope).
